# 路由

## 路由匹配

网关按以下顺序匹配请求的模型名：

1. 精确路由名。
2. 路由别名。
3. 前缀最长的通配路由。

API Key 可以限制可调用的路由，路由也可以限制可访问的 API Key。两边同时允许时请求才通过。

## 目标和回退

路由包含多个目标；每个目标把路由模型映射到一个凭证和一个上游模型。目标先按优先级升序分组，
组内按配置的策略排序。出现可回退失败时继续尝试下一个候选。

可回退失败包括限流、上游或网关超时、网络错误、上游凭证鉴权失败、额度耗尽和 5xx 响应。
表示请求本身无效的 4xx 会直接返回给客户端。流式请求只有在向客户端发出内容前才能回退。

## 同优先级策略

| 策略 | 值 | 行为 |
|---|---|---|
| 按权重随机 | `weighted` | 按权重无放回抽样 |
| 按顺序 | `order` | 一直使用第一个目标，直到失败或额度耗尽 |
| 轮流 | `rotate` | 优先最近会话最少的目标，数量相同时轮转 |
| 用得少的优先 | `usage` | 优先套餐窗口已用比例低的目标 |
| 先重置的优先 | `smart` | 接近耗尽时优先选择最早重置的套餐凭证 |
| 周进度 | `pace` | 按套餐剩余比例和剩余时间选择 |

后三种策略依赖可用的套餐额度信息。没有这类信息的普通凭证之间仍按权重随机排序。

## 会话粘性

LiteGate 从常见客户端请求头和请求字段识别会话。粘性让同一段对话尽量留在已经回答过它的凭证上，
以便命中上游提示词缓存。

默认范围是保留当前轮次的粘性；新轮次开始时，缓存仍有价值则继续保留。路由选项可以改成整个会话
或关闭粘性。显式命中的路由规则优先于粘性。

## 规则和意图路由

规则在目标选择前执行。命中的规则可以把请求转给另一条路由，也可以在指定时段跳过部分凭证。

条件包括：

- 提示 token 数。
- 是否包含图片或开启推理。
- 客户端接口格式。
- 请求标签。
- 本地时段。
- 分类得到的意图。

意图判断可以使用决策模型路由、本地 Laya 服务或后备判断路由。概率低于配置阈值时视为不命中。

## 并发、冷却和重试

凭证可以设置并发上限。凭证繁忙时优先改用其他目标；没有其他目标时进入排队。

冷却时长按失败类型区分。限流响应使用 `Retry-After`；额度耗尽使用上游返回的重置时刻；
鉴权、余额和普通失败使用配置的基础时长或指数增长时长。请求成功后清空连续失败计数。

所有候选都繁忙或暂时不可用时，网关可以等待后整轮重新评估路由，等待轮数和总时长受配置限制。
