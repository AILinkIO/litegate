# 架构

## 总览

LiteGate 是基于 Erlang/OTP 的 LLM API 网关。它对外提供 OpenAI 与 Anthropic 兼容接口，
把请求映射到可配置的路由和上游凭证，并记录用量、费用、日志和路由决策。

控制台挂在 `/console`。网关接口在 `/v1`，管理接口在 `/api`，健康检查和指标分别是
`/health` 与 `/metrics`。

## 技术选型

| 领域 | 选型 |
|---|---|
| 运行时 | Erlang/OTP 27 或更新版本 |
| 元数据 | Mnesia 磁盘表 |
| 请求数据 | Bitcask 与 C++23 NIF |
| HTTP 服务 | Cowboy |
| 上游 HTTP | Gun |
| 控制台 | React、TypeScript、Tailwind CSS、shadcn/ui、ECharts、Vite |

## 应用划分

| 应用 | 职责 |
|---|---|
| `lg_core` | 配置分层、Mnesia 建表和迁移、加密、指标、通用工具 |
| `lg_catalog` | 模型目录同步、用户覆盖、协议推断、定价查询 |
| `lg_provider` | 连接池、SSE 解析、OpenAI 和 Anthropic 适配、协议转换 |
| `lg_router` | 鉴权、路由解析、尝试排序、回退、额度、告警、中间件 |
| `lg_store` | 请求日志、对话、会话汇总、小时用量和数据保留 |
| `lg_web` | 网关路由、管理 API、账号认证、控制台资源 |

## 请求链路

```text
Cowboy
  -> API Key 鉴权
  -> 路由解析与规则判定
  -> 生成上游尝试顺序
  -> 协议适配和必要转换
  -> Gun 请求上游
  -> 流式或非流式响应
  -> 记录用量、日志和链路
```

路由解析同时受 API Key 的路由白名单和路由的访问控制约束。候选目标先按优先级分组，
再按组内策略排序。可重试失败会尝试下一个候选；客户端已经收到响应内容后不再回退。

## 数据模型

Mnesia 存放配置和元数据。用户覆盖读取时合并到同步来的模型目录之上。上游凭证保存加密后的
Key。路由引用凭证和上游模型名，不复制模型目录数据。

Bitcask 存放高流量运行数据：

| 目录 | 内容 |
|---|---|
| `logs` | 请求摘要和路由详情 |
| `msgs` | 脱敏后的请求和回复消息 |
| `idx` | 按 API Key、路由、用户的查询索引 |
| `usage` | 小时级用量和费用汇总 |
| `sessions` | 会话聚合状态 |

写入由单一 writer 批量执行。读取前会先 flush 相关 cask，因此查询结果包含刚完成的请求。

## 控制台

控制台是 React 单页应用，构建产物由 `lg_web` 托管。它包含凭证、路由、API Key、用户、
中间件和运行参数等配置页；请求、用量、会话、实时路由、上游健康和告警等运行页；
以及用于测试对话和协议转换的 Playground。

账号区分管理员和普通用户。普通用户只能管理自己的 API Key，也只能查看自己的请求和用量。
